    Fix invalid `timeout` and `forceKillAfterDelay` values
    
    Timers fire after 1ms when their delay is larger than 2147483647ms (about 24.8 days), so a large `timeout` or `forceKillAfterDelay` terminated the subprocess right away. Such values now throw instead.
    
    Fractional `timeout` values were accepted by asynchronous methods, but `spawnSync()` requires an integer, so synchronous methods failed with a raw `ERR_OUT_OF_RANGE` error. Both options now require integers, as their error messages already documented.
